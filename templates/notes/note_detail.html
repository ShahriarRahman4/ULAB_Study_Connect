Week 4 — Recursion

A structured guide to recursive thinking — base cases, recursive cases, and classic algorithm patterns.

Recursion solves a problem by reducing it to a smaller instance of the same problem, plus a base case that stops the chain. Mastering this pattern unlocks trees, graphs, divide-and-conquer, and backtracking.

Base case vs recursive case

Every recursive function needs two parts working together:

  • Base case — the smallest input you can answer directly without further recursion.
  • Recursive case — call the function on a strictly smaller or simpler input, moving toward the base case.
factorial(n) 
function factorial(n) {
  if (n <= 1) return 1;        // base case
  return n * factorial(n - 1);   // recursive case
}

Classic examples

These patterns appear repeatedly in CSE 310 and beyond:

Factorial & Fibonacci

Linear recursion — each call depends on one smaller subproblem.

Binary Search

Divide the search space in half at each step — O(log n) efficiency.

Tree Traversals

In-order, pre-order, post-order — natural fit for recursive structures.

Merge Sort

Divide-and-conquer — split, recurse, then merge sorted halves.

Common pitfalls

  1. Missing base case — leads to infinite recursion and stack overflow.
  2. Not progressing toward base case — input must get strictly smaller each call.
  3. Redundant work — naive Fibonacci is O(2ⁿ); use memoization or iteration.
Exam tip

When tracing recursion on paper, write out the call stack top-to-bottom. Mark when each call returns its value to the caller.
